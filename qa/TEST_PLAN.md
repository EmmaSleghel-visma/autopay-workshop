# Fraud Detection MVP — QA test plan

Owner: razvan-agent (QA). Source: Developer's plan (2026-10-23 10:37) and answers (10:43), a2a hub.
Test data and expected results are generated by `cases.py` → `data/*.csv` + `expected.json`.
`check.py` compares a build's actual output against `expected.json`; failures are tagged with their category.

**CSV: 105 cases: 19 positive, 40 negative, 46 corner** (`cases.py`, transactions + files).
**pain.001: 89 transaction cases (22 positive, 28 negative, 39 corner) in 27 file steps** (`pain001_cases.py`).

- **Positive** — valid, everyday input; the app does what it should (a rule fires, a clean payment passes).
- **Negative** — invalid or hostile input, or input that must *not* trigger a rule.
- **Corner** — boundaries and unusual-but-valid input.

## Confirmed by Developer

- Columns `transaction_id,debtor_account,creditor_account,amount,currency,due_date,created_date`; `YYYY-MM-DD`; `.` decimals; `created_date` optional.
- Flag codes: `HIGH_AMOUNT` (R1), `NEW_CREDITOR` (R2), `FAR_FUTURE_DUE` (R3), `UNSUPPORTED_CURRENCY`, `PAST_DUE_DATE`.
- Every imported transaction, flagged or not, becomes history (R2-04: second payment to B not flagged).
- Currency is trimmed and upper-cased on import (`nok`, ` eur `, `sek` work); any other text (`EURO`, `€`, `NOKK`) is kept as-is
  and is an unsupported currency; an empty or whitespace-only currency rejects the row (ERR-08, ERR-16).
- A bad row is rejected and reported with its line number; the rest of the file imports. A file missing a required column is rejected entirely.

## Decided by the Product Owner (via Developer, 10:53)

- Month-end: 31 Jan + 3 months = 30 Apr (last day of the month when the day doesn't exist).
- Due date before created date (or import date when there is none): flag `PAST_DUE_DATE` for manual review; the row is kept.
- ~~Non-NOK: every other rule still applies on top of `UNSUPPORTED_CURRENCY`.~~ Replaced by the 2026-10-23 10:20 decision below.
- Negative or zero amount: row rejected and reported as an error.
- A row with fewer or more values than the header: rejected with its line number (10:08).
- Import speed: under 30 s for 10,000 rows on Windows (10:08).
- pain.001 import is **in the MVP**, next to CSV. Version and a scrubbed sample requested from customer-mikael.

## Decided by the Product Owner, 2026-10-23 10:20 (currencies; commit 44d61cd)

- NOK, SEK and EUR are supported. `HIGH_AMOUNT` uses a limit per currency, in that currency, no conversion:
  **NOK > 10,000.00, SEK > 10,000.00, EUR > 1,000.00**; exactly the limit is not flagged.
- Any other currency (USD, GBP, DKK, typos like `EURO`) is `UNSUPPORTED_CURRENCY` and **never** `HIGH_AMOUNT`, whatever the amount.
- `NEW_CREDITOR`, `FAR_FUTURE_DUE` and `PAST_DUE_DATE` apply to every currency, supported or not.
- Customer sample v03: `E2E-0003` (EUR 650 to a new creditor) is now only `NEW_CREDITOR`.

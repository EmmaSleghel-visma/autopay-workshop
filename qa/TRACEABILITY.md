# Fraud Detection MVP — requirements traceability

Requirement → test plan case ids → automated tests that cover it. Results come from CI
(`.github/workflows/qa.yml`, JUnit XML in the `qa-reports-*` artifacts), so the status column is not
maintained by hand.

Case ids: plain ids (`R1-02`, `FILE-07`) are CSV cases in `qa/cases.py`; ids prefixed `pain:` are
pain.001 cases in `qa/pain001_cases.py` (the two files reuse some ids, e.g. `R1-01`, `FILE-01`).
Tests are `file::function`; `tests/qa/` is the QA suite, `tests/*.py` are the developers' unit tests.
`[slow]` = runs only in the `slow` CI job (PRs to `main`, manual runs).

Shared data-driven tests run every case of their category at once, so they appear on many rows:

| Short name | Test |
|---|---|
| RULES | `tests/qa/test_qa_rules.py::test_rules_positive` / `test_rules_negative` / `test_rules_corner` |
| PIPE | `tests/qa/test_qa_pipeline.py::test_positive_cases_get_the_expected_flags` / `test_negative_…` / `test_corner_…` |
| PAIN | `tests/qa/test_qa_pain001.py::test_positive_cases_get_the_expected_flags` / `test_negative_…` / `test_corner_…` |
| DT | `tests/qa/test_qa_decision_table.py::test_every_combination_with_created_date`, `test_every_combination_falls_back_to_import_date` |
| PROP | `tests/qa/test_qa_properties.py` (Hypothesis properties + `test_pipeline_matches_oracle`) |

## Regression rule

Every bug found gets (1) a case in `qa/cases.py` or `qa/pain001_cases.py`, so it lives in the
generated data and `expected.json`, and (2) the automated test that fails on the bug and passes on
the fix. A bug is closed only when that test is green in CI. Fixed bugs keep their case and test.
